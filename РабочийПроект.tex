\subsubsection{Спецификация класса UserApiController}
UserApiController (Компонент управления пользователями через API)

Описание: Управляет операциями, связанными с регистрацией пользователей и получением информации о текущем авторизованном пользователе через API. Взаимодействует с сущностью User и использует формы для обработки данных.

Валидация данных:
\begin{itemize}
	\item в методе userRegistration() используется форма ApiRegistrationFormType для валидации входных данных, таких как email и пароль, перед их сохранением;
	\item данные, полученные из HTTP-запросов в формате JSON, проверяются на соответствие требованиям формы.
\end{itemize}

Безопасность:
\begin{itemize}
	\item пароли хэшируются с использованием UserPasswordHasherInterface перед сохранением в базе данных;
	\item доступ к информации об авторизованном пользователе осуществляется через токен безопасности (security.token{\_}storage).
\end{itemize}

Роли и права:
\begin{itemize}
	\item взаимодействует с моделью UserRoles для получения информации о ролях пользователей;
	\item пакет FOSRestBundle используется для обработки REST-запросов и формирования ответов.
\end{itemize}

Основные методы:
\begin{itemize}
	\item userRegistration(Request \$request, UserRolesRepository \$userRolesRepository, EntityManagerInterface \$entityManager, UserPasswordHasherInterface \$passwordHasher): регистрирует нового пользователя, валидирует данные, хэширует пароль и сохраняет пользователя в базе данных;
	\item getAuthUserInfo(UserRepository \$repository): возвращает информацию об авторизованном пользователе;
	\item getUserRoles(UserRolesRepository \$repository): возвращает список всех ролей пользователей.
\end{itemize}
Зависимости:
\begin{itemize}
	\item взаимодействует с сущностями User и UserRoles;
	\item использует ApiRegistrationFormType для обработки форм регистрации;
	\item зависит от EntityManagerInterface для работы с базой данных;
	\item использует FOSRestBundle для обработки REST-запросов и формирования ответов в формате JSON;
	\item применяет UserPasswordHasherInterface для безопасного хэширования паролей.
\end{itemize}

\subsubsection{Спецификация класса VacancyApiController}
VacancyApiController (Компонент управления вакансиями через API)

Описание: Управляет операциями, связанными с вакансиями, такими как создание, получение списка вакансий, получение данных об отдельной вакансии и получение вакансий, связанных с авторизованным пользователем. Реализует REST API и взаимодействует с сущностью Vacancy.

Валидация данных:

\begin{itemize}
	\item в методе newVacancy() используется форма ApiVacancyType для валидации входных данных, полученных в формате JSON;
	\item валидация обеспечивает корректность полей, необходимых для создания вакансии.
\end{itemize}

Безопасность:

\begin{itemize}
	\item доступ к информации о вакансиях текущего пользователя осуществляется через метод getUser(), который возвращает данные авторизованного пользователя;
	\item используется FOSRestBundle для обработки REST-запросов и формирования стандартизированных ответов.
\end{itemize}

Роли и права:
\begin{itemize}
	\item доступ к методу userResume() ограничен для авторизованных пользователей, так как он возвращает вакансии, связанные с текущим пользователем.
\end{itemize}

Основные методы:
\begin{itemize}
	\item getManyVacancies(Request \$request, VacancyRepository \$vacancyRepository): возвращает отфильтрованный список вакансий с пагинацией и информацией о фильтрах;
	\item newVacancy(Request \$request, EntityManagerInterface \$entityManager): создает новую вакансию, валидирует данные и сохраняет их в базе данных;
	\item getSingleVacancy(Vacancy \$vacancy, VacancyRepository \$vacancyRepository): возвращает данные об одной вакансии по её идентификатору;
	\item userResume(VacancyRepository \$vacancyRepository): возвращает список вакансий, связанных с авторизованным пользователем.
\end{itemize}

Зависимости:
\begin{itemize}
	\item взаимодействует с сущностью Vacancy и репозиторием VacancyRepository;
	\item использует ApiVacancyType для обработки форм создания вакансий;
	\item зависит от EntityManagerInterface для работы с базой данных;
	\item использует FilterService для обработки и применения фильтров в методе getManyVacancies;
	\item применяет FOSRestBundle для обработки REST-запросов и формирования JSON-ответов.
\end{itemize}

\subsubsection{Спецификация класса VacancyParametersApiController}
VacancyParametersApiController (компонент управления параметрами вакансий через API)

Описание:Управляет операциями получения параметров вакансий через REST API. Обеспечивает получение списка всех параметров определенного типа или данных об одном параметре по его идентификатору. Взаимодействует с сущностями, связанными с параметрами вакансий.

Валидация данных:
\begin{itemize}
	\item отсутствует валидация входных данных, так как методы обрабатывают GET-запросы с параметрами, передаваемыми в URL;
	\item проверяется существование запрошенного типа параметра вакансии, в случае ошибки выбрасывается исключение NotFoundHttpException.
\end{itemize}

Связи:
\begin{itemize}
	\item параметры вакансий связаны с сущностями в пространстве имен App/Entity/Vacancy/Vacancy, определяемыми динамически через параметр vacancyParameter.
\end{itemize}

Безопасность:
\begin{itemize}
	\item использует FOSRestBundle для обработки REST-запросов и формирования стандартизированных JSON-ответов;
	\item не реализует дополнительной аутентификации или авторизации, доступ к методам предполагается открытым.
\end{itemize}

Основные методы:
\begin{itemize}
	\item getManyVacancyParameters(string \$vacancyParameter, ManagerRegistry \$doctrine): возвращает список всех параметров вакансии для указанного типа;
	\item getSingleVacancyParameters(string \$vacancyParameter, int \$id, ManagerRegistry \$doctrine): возвращает данные об одном параметре вакансии по его идентификатору.
\end{itemize}

Зависимости:
\begin{itemize}
	\item взаимодействует с сущностями, определенными в пространстве имен App/Entity/Vacancy/Vacancy, через ManagerRegistry для динамического получения репозитория;
	\item использует FOSRestBundle для обработки REST-запросов и формирования JSON-ответов;
	\item применяет Symfony/Component/HttpKernel/Exception/NotFoundHttpException для обработки ошибок при неверном типе параметра.

	\item проверяет корректность полей резюме перед сохранением в базе данных.

\begin{itemize}

	\item резюме связано с пользователем через поле user, устанавливаемое автоматически для авторизованного пользователя.
\end{itemize}

Безопасность:
\begin{itemize}
	\item использует FOSRestBundle для обработки REST-запросов и формирования стандартизированных JSON-ответов;

\begin{itemize}

\subsubsection{Спецификация класса FilterService}
FilterService (сервис для управления фильтрацией данных)

Описание: Отвечает за обработку и применение фильтров к запросам Doctrine на основе параметров HTTP-запросов. Парсит фильтры из запросов, определяет фильтруемые поля сущностей с помощью атрибута Filterable и применяет фильтры к QueryBuilder. Инкапсулирует логику фильтрации данных для выборки сущностей из базы данных.

Основные задачи:
\begin{itemize}
	\item парсинг параметров фильтров из HTTP-запросов;
	\item определение фильтруемых полей сущностей через атрибут Filterable;
	\item применение фильтров к запросам Doctrine с поддержкой различных типов фильтрации (точное совпадение, LIKE, диапазоны, даты);
	\item обработка связанных сущностей через LEFT JOIN;
	\item проверка валидности значений фильтров и их преобразование (например, диапазоны вида "100-500").
\end{itemize}

Основные методы:
\begin{itemize}
	\item parseFilters(Request \$request): парсит параметры фильтров из HTTP-запроса и возвращает их в виде массива;
	\item applyFilters(QueryBuilder \$qb, array \$filters, string \$entityClass): применяет фильтры к QueryBuilder на основе фильтруемых полей сущности;
	\item getFilterableFields(ReflectionClass \$reflection): возвращает массив фильтруемых полей сущности, определенных атрибутом Filterable;
	\item applyFilter(QueryBuilder \$qb, string \$type, string \$field, mixed \$value, string \$paramName): применяет фильтр к QueryBuilder в зависимости от типа фильтра;
	\item applyRangeFilter(QueryBuilder \$qb, string \$field, mixed \$value, string \$paramName): применяет фильтр диапазона значений;
	\item applyDateRangeFilter(QueryBuilder \$qb, string \$field, mixed \$value, string \$paramName): применяет фильтр диапазона дат;
	\item addJoin(QueryBuilder \$qb, string \$joinConfig): добавляет LEFT JOIN к QueryBuilder для связанных сущностей;
	\item getFieldPath(Filterable \$filterable, string \$rootAlias): определяет путь к полю для фильтрации;

StringHelperService (Сервис для обработки строк)

Описание: Отвечает за обработку и преобразование строк, включая генерацию случайных строк, создание слаг-идентификаторов, транслитерацию русского текста в английский, извлечение аргументов из шаблонов строк и преобразование регистра. Инкапсулирует вспомогательные функции для работы со строками в приложении.

Основные задачи:
\begin{itemize}
	\item генерация случайных строк заданной длины;
	\item создание уникальных слаг-идентификаторов для сущностей;
	\item транслитерация русских символов в латинские для создания читаемых URL;
	\item извлечение аргументов из шаблонов строк формата \%argument\$s;
	\item преобразование первой буквы строки в верхний регистр с учетом многобайтных кодировок.
\end{itemize}

Основные методы:
\begin{itemize}
	\item getRandomStr(int \$length): генерирует случайную строку заданной длины из набора символов;
	\item generateSlugForEntity(string \$string, bool \$unique = true): создает слаг из строки с возможным добавлением уникального суффикса;
	\item translitRuToEn(string \$text): транслитерирует русский текст в английский, заменяя специальные символы на дефисы;
	\item getStringArguments(\$format): извлекает аргументы из шаблона строки формата \%argument\$s;
	\item my\_mb\_ucfirst(string \$string): преобразует первую букву строки в верхний регистр с учетом многобайтных кодировок.
\end{itemize}

Зависимости:
\begin{itemize}
	\item использует встроенные PHP-функции для работы со строками (mb\_strtolower, mb\_ereg\_replace, strtr);
	\item зависит от Exception для обработки ошибок при генерации случайных строк;
	\item не имеет прямых зависимостей от внешних библиотек или фреймворков.
\end{itemize}

\subsection{Тестирование программной системы}

\subsubsection{Модульное тестирование классов и методов программы}

Модульное тестирование в рамках разработки программноинформаци-
онной системы для управления данными о подготовке к производству метал-
локонструкций проводится с целью выявления ошибок в работе отдельных
компонентов программы. Оно позволяет убедиться, что каждый класс и ме-
тод системы функционируют корректно при различных сценариях использо-
вания.

Описание процесса модульного тестирования:

Модульное тестирование фокусируется на проверке правильности ра-
боты небольших единиц программы — классов и методов, что помогает
быстро локализовать и устранять ошибки на ранних этапах разработки. В
данной системе тестирование охватывает такие ключевые компоненты, как
управление пользователями, обработка заказов, работа с чертежами, матери-
алами, задачами и отчетами, а также взаимодействие с хранилищем данных
и другими внешними компонентами.

Основные цели модульного тестирования:
\begin{enumerate}
	\item Изоляция: Каждый тест проверяет работу одного класса или метода,
	что позволяет точно определить место возникновения ошибки.
	\item Автоматизация: Модульные тесты выполняются автоматически с
	использованием таких инструментов, как PHPUnit (для PHP), что ускоряет
	процесс разработки и исправления ошибок.
	\item Покрытие: Тесты охватывают все ключевые методы системы, вклю-
	чая проверку обработки граничных случаев (например, пустые или некор-
	ректные входные данные).
\end{enumerate}

\subsection{Системное тестирование платформы}

Целью данного тестирования является проверка функциональности, надежности и производительности веб-платформы для поиска работы.
Системное тестирование позволяет выявить и устранить ошибки, а такжеоценить соответствие системы предъявленным требованиям.

Все тестовые сценарии должны проходить успешно без критических сбоев. Платформа должна обеспечивать стабильную и удобную работу пользователей в соответствии с установленными бизнес-процессами. Результаты тестирования будут использованы для повышения качества, надежности и пользовательского опыта сервиса по поиску работы.

\textbf{1) Запуск системы}

Описание: система должна запускаться без ошибок и отображать глав-
ное окно интерфейса.
