\subsubsection{Спецификация класса UserApiController}

UserApiController (Компонент управления пользователями через API).

Описание: управляет операциями, связанными с регистрацией пользователей и получением информации о текущем авторизованном пользователе через API. Взаимодействует с сущностью User и использует формы для обработки данных.

Валидация данных:
\begin{itemize}
	\item в методе userRegistration() используется форма ApiRegistrationFormType для валидации входных данных, таких как email и пароль, перед их сохранением;
	\item данные, полученные из HTTP-запросов в формате JSON, проверяются на соответствие требованиям формы.
\end{itemize}

Безопасность:
\begin{itemize}
	\item пароли хэшируются с использованием UserPasswordHasherInterface перед сохранением в базе данных;
	\item доступ к информации об авторизованном пользователе осуществляется через токен безопасности (security.token{\_}storage).
\end{itemize}

Роли и права:
\begin{itemize}
	\item взаимодействует с моделью UserRoles для получения информации о ролях пользователей;
	\item пакет FOSRestBundle используется для обработки REST-запросов и формирования ответов.
\end{itemize}

Основные методы:
\begin{itemize}
	\item userRegistration(Request \$request, UserRolesRepository \$userRolesRepository, EntityManagerInterface \$entityManager, UserPasswordHasherInterface \$passwordHasher): регистрирует нового пользователя, валидирует данные, хэширует пароль и сохраняет пользователя в базе данных;
	\item getAuthUserInfo(UserRepository \$repository): возвращает информацию об авторизованном пользователе;
	\item getUserRoles(UserRolesRepository \$repository): возвращает список всех ролей пользователей.
\end{itemize}
Зависимости:
\begin{itemize}
	\item взаимодействует с сущностями User и UserRoles;
	\item использует ApiRegistrationFormType для обработки форм регистрации;
	\item зависит от EntityManagerInterface для работы с базой данных;
	\item использует FOSRestBundle для обработки REST-запросов и формирования ответов в формате JSON;
	\item применяет UserPasswordHasherInterface для безопасного хэширования паролей.
\end{itemize}

\subsubsection{Спецификация класса VacancyApiController}
VacancyApiController (Компонент управления вакансиями через API).

Описание: управляет операциями, связанными с вакансиями, такими как создание, получение списка вакансий, получение данных об отдельной вакансии и получение вакансий, связанных с авторизованным пользователем. Реализует REST API и взаимодействует с сущностью Vacancy.

Валидация данных:

\begin{itemize}
	\item в методе newVacancy() используется форма ApiVacancyType для валидации входных данных, полученных в формате JSON;
	\item валидация обеспечивает корректность полей, необходимых для создания вакансии.
\end{itemize}

Безопасность:

\begin{itemize}
	\item доступ к информации о вакансиях текущего пользователя осуществляется через метод getUser(), который возвращает данные авторизованного пользователя;
	\item используется FOSRestBundle для обработки REST-запросов и формирования стандартизированных ответов.
\end{itemize}

Роли и права:
\begin{itemize}
	\item доступ к методу userResume() ограничен для авторизованных пользователей, так как он возвращает вакансии, связанные с текущим пользователем.
\end{itemize}

Основные методы:
\begin{itemize}
	\item getManyVacancies(Request \$request, VacancyRepository \$vacancyRepository): возвращает отфильтрованный список вакансий с пагинацией и информацией о фильтрах;
	\item newVacancy(Request \$request, EntityManagerInterface \$entityManager): создает новую вакансию, валидирует данные и сохраняет их в базе данных;
	\item getSingleVacancy(Vacancy \$vacancy, VacancyRepository \$vacancyRepository): возвращает данные об одной вакансии по её идентификатору;
	\item userResume(VacancyRepository \$vacancyRepository): возвращает список вакансий, связанных с авторизованным пользователем.
\end{itemize}

Зависимости:

\begin{itemize}
	\item взаимодействует с сущностью Vacancy и репозиторием VacancyRepository;
	\item использует ApiVacancyType для обработки форм создания вакансий;
	\item зависит от EntityManagerInterface для работы с базой данных;
	\item использует FilterService для обработки и применения фильтров в методе getManyVacancies;
	\item применяет FOSRestBundle для обработки REST-запросов и формирования JSON-ответов.
\end{itemize}

\subsubsection{Спецификация класса VacancyResponseApiController}

VacancyResponseApiController (компонент управления откликами на вакансии через API).

Описание: управляет операциями, связанными с откликами на вакансии, включая создание нового отклика и получение списка откликов, связанных с авторизованным пользователем. Реализует REST API и взаимодействует с сущностью VacancyResponse.

Валидация данных:
\begin{itemize}
	\item в методе newVacancyResponse() используется форма VacancyResponseApiType для валидации входных данных, полученных в формате JSON;
	\item проверяет наличие активных резюме у пользователя перед созданием отклика;
	\item при отсутствии активных резюме выбрасывается исключение HttpException с кодом 300.
\end{itemize}

Связи:
\begin{itemize}
	\item отклики на вакансии связаны с сущностями Resume, VacancyResponseStatus и пользователем через поле initiator.
\end{itemize}

Безопасность:
\begin{itemize}
	\item использует FOSRestBundle для обработки REST-запросов и формирования стандартизированных JSON-ответов;
	\item доступ к методу userResume() ограничен для авторизованных пользователей через getUser();
	\item метод newVacancyResponse() доступен только пользователям с активными резюме.
\end{itemize}

Уведомления:
\begin{itemize}
	\item не реализует уведомления для пользователей, так как методы возвращают только HTTP-ответы в формате JSON;
	\item в случае отсутствия активных резюме возвращается сообщение об ошибке в формате JSON.
\end{itemize}

Основные методы:
\begin{itemize}
	\item newVacancyResponse(Request \$request, VacancyResponseStatusRepository \$vacancyResponseStatusRepository, EntityManagerInterface \$entityManager, UserRepository \$userRepository): создает новый отклик на вакансию, валидирует данные и сохраняет их в базе данных;
	\item userResume(VacancyResponseRepository \$vacancyResponseRepository): возвращает список откликов, связанных с авторизованным пользователем.
\end{itemize}

Зависимости:
\begin{itemize}
	\item взаимодействует с сущностями VacancyResponse, Resume, VacancyResponseStatus и репозиториями VacancyResponseRepository, VacancyResponseStatusRepository, UserRepository;
	\item использует VacancyResponseApiType для обработки форм создания откликов;
	\item зависит от Doctrine/ORM/EntityManagerInterface для работы с базой данных;
	\item использует FOSRestBundle для обработки REST-запросов и формирования JSON-ответов;
	\item применяет Symfony/Component/HttpKernel/Exception/HttpException для обработки ошибок при отсутствии активных резюме.
\end{itemize}

\subsection{Тестирование программной системы}

\subsubsection{Модульное тестирование классов и методов программы}

Модульное тестирование в рамках разработки программноинформаци-
онной системы для управления данными о подготовке к производству метал-
локонструкций проводится с целью выявления ошибок в работе отдельных
компонентов программы. Оно позволяет убедиться, что каждый класс и ме-
тод системы функционируют корректно при различных сценариях использо-
вания.

Описание процесса модульного тестирования.

Модульное тестирование фокусируется на проверке правильности ра-
боты небольших единиц программы — классов и методов, что помогает
быстро локализовать и устранять ошибки на ранних этапах разработки. В
данной системе тестирование охватывает такие ключевые компоненты, как
управление пользователями, обработка заказов, работа с чертежами, матери-
алами, задачами и отчетами, а также взаимодействие с хранилищем данных
и другими внешними компонентами.

Основные цели модульного тестирования:
\begin{enumerate}
	\item Изоляция. 
	
	Каждый тест проверяет работу одного класса или метода,
	что позволяет точно определить место возникновения ошибки.
	
	\item Автоматизация. 
	
	Модульные тесты выполняются автоматически с
	использованием таких инструментов, как PHPUnit (для PHP), что ускоряет
	процесс разработки и исправления ошибок.
	
	\item Покрытие. 
	
	Тесты охватывают все ключевые методы системы, вклю-
	чая проверку обработки граничных случаев (например, пустые или некор-
	ректные входные данные).
	
\end{enumerate}

\subsection{Системное тестирование платформы}

Целью данного тестирования является проверка функциональности, надежности и производительности веб-платформы для поиска работы.
Системное тестирование позволяет выявить и устранить ошибки, а такжеоценить соответствие системы предъявленным требованиям.

Все тестовые сценарии должны проходить успешно без критических сбоев. Платформа должна обеспечивать стабильную и удобную работу пользователей в соответствии с установленными бизнес-процессами. Результаты тестирования будут использованы для повышения качества, надежности и пользовательского опыта сервиса по поиску работы.
